# 多平台发布工具 · 使用说明

> 一句话：把**一篇 Markdown 博客文章**（或一个网页链接），一键 AI 排版并发布到
> **公众号 / 小红书 / 知乎 / CSDN / 掘金** 五大平台；标题自动取「吸睛钩子标题」，
> 卡在需要人工的那一步（扫码 / 点发布）时，用飞书机器人私聊给你发可点链接。

---

## 一、有什么用

写博客最累的不是写，是**搬运**：同一篇文章要在 5 个平台分别登录、各自排版、各填一遍标题/标签/封面。
这个工具把搬运这件事自动化：

- **一份 Markdown → 五个平台**。源就是你 Hexo 博客的 `.md`，不用为每个平台重排。
- **排版自动适配每个平台**：公众号要内联样式 HTML、小红书要竖版图片、知乎/CSDN/掘金各有编辑器，工具按平台走对应路线。
- **标题自动取吸睛钩子**（B 站「学过石油的语文老师」杨佳琦式：短句 + 问号感叹号 + 痛点悬念）。
- **发布素材显式生成**：公众号封面 prompt、摘要高光句、小红书 hook、CSDN/掘金摘要都由 skill 读完文章后生成，不用正文开头硬截。
- **默认不真发**：先填成草稿 / 填好待审，你看过没问题再 `--post` 真发。
- **卡点飞书提醒**：需要你扫码或点「发布」时，机器人私聊发一张带按钮的卡片，点进去就能操作。

## 二、怎么实现的（架构）

**设计哲学：skill 当大脑，core + CLI 当手。**
- **大脑（skill）**＝ AI 编排：读文章、取标题、按系列选排版主题、判断群发还是仅发表、处理卡点、发飞书。
- **手（脚本）**＝ 确定性代码：真正去开浏览器、填表、点按钮。既能被 AI 调，也能你手动 / cron 跑。

```
┌─────────────────────────── 大脑：各平台 skill（SKILL.md） ───────────────────────────┐
│  wechat-mp-publish   xiaohongshu-cards   zhihu-publish   csdn-publish   juejin-publish │
└───────────────┬──────────────────────────────────────────────────────────────────────┘
                │ 调用
┌───────────────▼─── 手：统一 CLI publish-cli.mjs（薄调度，不写浏览器逻辑） ───────────────┐
│   wechat │ wechat-send │ xiaohongshu │ zhihu │ csdn │ juejin │ all                       │
└───────────────┬──────────────────────────────────────────────────────────────────────┘
                │ 复用
┌───────────────▼─────────── 共享核心 _publish_core/ ───────────────────────────────────┐
│  chromium.cjs/.mjs（统一找 Playwright 自带 Chromium）                                    │
│  title.mjs + title-playbook.md（吸睛标题：规则 + 长度校验）                                │
│  README.md（核心说明）                                                                    │
│  飞书通知 notify_lark.cjs（在 wechat-mp-publish/scripts/，带按钮私聊卡片）                  │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

**关键技术点：**
- **浏览器**：统一用 **Playwright 自带 Chromium**（不是你日常的 Chrome，互不干扰），装在仓库内
  `.pw-browsers/`（避开系统缓存清理）。每个平台一个**持久登录态目录**（`.xxx-browser/`），**扫一次码长期复用**。
- **个人号没有发布 API**：公众号个人主体 2025-07 起失去发布 API 权限，知乎/小红书/CSDN/掘金本就没有好用的对外发文 API，所以**全部走网页自动化**。
- **排版按平台分路**：
  | 平台 | 正文怎么进编辑器 |
  |---|---|
  | 公众号 | Markdown → `@wenyan-md/core` 渲染成**内联样式 HTML** + AI 封面，剪贴板粘进 ProseMirror |
  | 小红书 | Markdown → HTML/CSS 模板 → Playwright 截成 **1080×1440 竖版卡片图**，上传 |
  | 知乎 | Markdown → 渲染 HTML → **剪贴板粘进 Draft.js**（丢内联样式、留结构 = 知乎原生排版）|
  | CSDN | 编辑器是 **markdown 原生**（cledit），**直接灌 raw markdown** |
  | 掘金 | 编辑器是 **markdown 原生**（Bytemd/CodeMirror），**直接灌 raw markdown** |
- **发布卡点三级兜底**：locator 点按钮 → 坐标点 → 都不行就**保持窗口 + 飞书发链接让你手动点**。
- **飞书通知**：CC 专用机器人（与 Codex 桥接隔离）。文本含链接时发**交互卡片**（蓝按钮「🚀 打开页面去发布」+ 明文链接），**默认私聊**。

## 三、目录结构

```
skills/skills/
├── 多平台发布工具说明.md          ← 本文件
├── publish-cli.mjs                ← 统一 CLI（总入口）
├── _publish_core/                 ← 共享核心
│   ├── chromium.cjs / chromium.mjs    找浏览器
│   ├── title.mjs                      标题长度校验
│   ├── title-playbook.md              取标题公式（给 AI 读）
│   └── README.md
├── wechat-mp-publish/             ← 公众号（含 notify_lark.cjs、wenyan 渲染、AI 封面、群发）
├── xiaohongshu-cards/             ← 小红书（卡片图生成 + 发布）
├── zhihu-publish/                 ← 知乎
├── csdn-publish/                  ← CSDN（新）
└── juejin-publish/                ← 掘金（新）
```
每个平台目录里都有一个 `SKILL.md`（给 AI 看的操作手册）和 `scripts/`（登录脚本 + 发布脚本）。

## 四、怎么用

> 下面命令默认在 `skills/skills/` 目录下执行。

### 0）一次性准备：登录（扫一次码，长期复用）
```bash
node wechat-mp-publish/scripts/...        # 公众号（已登录）
node xiaohongshu-cards/scripts/xhs_login.cjs
node zhihu-publish/scripts/zhihu_login.cjs
node csdn-publish/scripts/csdn_login.cjs
node juejin-publish/scripts/juejin_login.cjs
```

### 1）发布前：取吸睛标题（必做，别用平铺标题）
按 `_publish_core/title-playbook.md` 的公式想 3 个候选、挑 1 个，再校验长度：
```bash
node _publish_core/title.mjs --title "AI 到底怎么来的？一个寓言讲清 70 年！" --platform zhihu
# platform: wechat(≤64) | xiaohongshu(≤20) | zhihu(≤100) | csdn(≤100) | juejin(≤100)
```

### 2）发布（统一 CLI）
```bash
# 单平台，填好不发（草稿/待审）——安全默认
node publish-cli.mjs zhihu  --file /abs/article.md --title "..."
node publish-cli.mjs csdn   --file /abs/article.md --title "..." --tags "AI,Agent" --column "AI 寓言课"
node publish-cli.mjs wechat --file /abs/article.md --title "..." --cover-prompt "故事高光画面..." --digest "摘要高光句..."
node publish-cli.mjs juejin --file /abs/article.md --title "..." --category "人工智能" --tags "机器学习" --summary "50 到 100 字摘要..."

# 一条命令铺到全部 5 平台（都只到草稿/填好，绝不真发）
node publish-cli.mjs all --file /abs/article.md --title "..."

# 确认无误后，逐平台真发（--post）
node publish-cli.mjs zhihu  --file /abs/article.md --post
node publish-cli.mjs csdn   --file /abs/article.md --post --tags "AI,Agent"
node publish-cli.mjs wechat-send --appmsgid <草稿id> --post           # 公众号群发已有草稿
node publish-cli.mjs wechat-send --appmsgid <草稿id> --post --no-masssend  # 仅发表不推送
```

### 3）CLI 速查
| platform | 不带 --post（默认） | 带 --post |
|---|---|---|
| `wechat` | 渲染 → 存公众号草稿 | web 直接发布 |
| `wechat-send` | 只预览（安全闸门） | 群发 / 仅发表已有草稿 |
| `xiaohongshu` | 生成卡片图 + 填发布页 | 真发 |
| `zhihu` | 填标题+正文到草稿 | 真发 |
| `csdn` | 填标题+正文到编辑器 | 真发 |
| `juejin` | 填标题+正文到草稿 | 真发 |
| `all` | 上面前 4 个都填好不发 | **永远忽略 --post**（要真发请逐平台） |

`node publish-cli.mjs --help` 看全部选项。

### 4）各平台特有参数
- **wechat**：`--theme`（公众号主题）`--hl-theme`（代码高亮）`--url`（传网页链接代替 --file）`--no-cover`（跳过 AI 封面）`--digest`（摘要高光句）`--cover-prompt`（AI 封面提示）`--author`
- **wechat-send**：`--appmsgid <id>`（指定要群发的草稿）`--no-masssend`（仅发表不推送）
- **xiaohongshu**：`--theme literary|blue` `--out <卡片输出目录>`
- **zhihu**：`--topic <话题>`（仅 --post 时尝试添加）
- **csdn**：`--tags a,b,c` `--column "分类专栏"` `--summary "摘要"`
- **juejin**：`--category "分类"`（发布必选）`--tags 单个标签` `--column "专栏"` `--summary "50-100 字摘要"`

## 五、安全与约定（重要）

- **默认不真发**：不传 `--post` 一律只到草稿 / 填好待审 / 预览。`--post` 才对外发布。
- **`all` 永不真发**：批量铺开只用来一次性准备草稿，要真发请对单平台逐个执行。
- **公众号**：默认**群发优先，失败/扫码超时回退仅发表不推送**；网页端每次发表都要过一道「微信验证」扫码（腾讯强制，真人扫，绕不过）。
- **小红书硬规则**：正文/卡片/标题**一律不得出现「公众号」或任何跨平台引流**（违规广告）。
- **掘金小册**：付费、多章节、需掘金审批「开设小册」，**不自动创建**；本工具只做文章 + 专栏/分类。
- **飞书提醒**：需要你操作时（扫码 / 点发布）机器人私聊发带按钮的链接卡片。
- **二维码图片提醒**：默认只保证发待操作文本/卡片；二维码图片需要 bot 图片上传权限和发送成功日志，不能默认假设已发出。
- **不打印** token / cookie / secret。

## 七、常见问题 / 坑

- **浏览器打不开 / 找不到 Chromium**：重装到仓库内 `.pw-browsers/`：
  `PLAYWRIGHT_BROWSERS_PATH=<repo>/.pw-browsers node_modules/.bin/playwright install chromium`
- **提示未登录（exit 2）**：先跑对应平台的 `*_login.cjs` 扫码。
- **同一平台别并发跑两个脚本**：持久 profile 会被 Chromium 锁住。
- **CSDN/掘金 选择器**：来自公开实测，标 ⚠ 的在 `SKILL.md` 里，首次真登录后用 `*_login.cjs` dump 的结果复核。
- **临时文件**：截图/日志默认落脚本目录，可用 `DIAG_OUT=<dir>` 改到别处。
- **DOM 和截图怎么用**：DOM/URL/日志是判断流程的主依据；截图只用于二维码、封面/卡片预览、遮罩、窗口焦点、按钮可见但不可点这类视觉状态。
- **能不能直接发请求**：可以作为后续 API discovery 方向，但必须先抓到真实 endpoint、cookie/CSRF/token、请求体、签名参数和扫码后的状态机，并能回读成功页。不能 mock 平台响应骗过本地脚本，也不能绕过真人验证。
- **需要浏览器/网络的命令**：在本环境里跑要带 `dangerouslyDisableSandbox`，并用后台跑、读输出文件看结果。
