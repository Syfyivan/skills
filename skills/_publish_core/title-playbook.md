# 发布前吸睛标题手册（title-playbook）

> 多平台发布前「取标题」的统一规则。发布脚本（公众号 / 小红书 / 知乎 / CSDN / 掘金）默认用文章
> frontmatter 的 `title`，那是**归档用的平铺标题**，不适合直接对外发。发布前必须按本手册
> 重写成「钩子标题」，再用同目录的 `title.mjs` 做机械校验，最后用 `--title` 传给发布脚本。
>
> 风格参照 B 站 UP 主「学过石油的语文老师」（杨佳琦）的爆款标题：短句、高频问号感叹号、
> 痛点开场、不剧透、口语喊话。本手册的范例统一围绕当前在发的题材 **「AI 与 Agent 大寓言课」**
> （用寓言故事讲 AI / Agent 概念）。

---

## 一、取标题公式（按这 6 条造句）

1. **短句切分**：把一句话拆成 2-3 个短促小节，用标点断开，别写成一长串从句。
2. **高频「？」「！」断句**：一个标题常 **1-2 个问号 + 1 个感叹号**。问号制造悬念，感叹号给情绪。
3. **痛点 / 悬念提问开场**：开头先戳读者的困惑或好奇（「AI 为啥会胡说？」），**不要在标题里给答案**。
4. **反差 / 夸张承诺 或 行动召唤收尾**：结尾要么给个反差大的承诺（「一个寓言讲穿！」），
   要么喊一句行动（「看完这篇！」「发给同桌！」）。
5. **口语喊话感**：像当面跟人说话，用「你」「凭啥」「来了」「治好它」这类口语词，别端着。
6. **数字 / 具体物增加确定感**：能加就加——「3 分钟」「三起三落」「一个寓言」「图书管理员」，
   具体的名词比抽象概念更抓人。

**避免**：`XX 详解 / 第 N 讲 / 入门 / 全解析 / 一文读懂 / 基础知识` 这类平铺课程式标题——
信息量为零、没有情绪、不制造悬念。

## 二、改写范例（平铺 → 钩子，均为「大寓言课」题材）

| 平铺式（别这么写） | 钩子式（这么写） | 用了哪几招 |
| --- | --- | --- |
| 第 01 讲：AI 发展简史 | **AI 这几十年？三起三落！一个寓言带你看完** | 悬念提问 + 数字反差 + 行动召唤 |
| 第 02 讲：神经网络是怎么学习的 | **机器也能开窍？神经网络怎么学会的？看这个寓言！** | 痛点提问串 + 口语 + 行动召唤 |
| 第 04 讲：什么是大语言模型（LLM） | **AI 凭啥张口就来？大模型的脑子！一个寓言讲穿！** | 悬念提问 + 口语 + 夸张承诺 |
| 第 06 讲：Token 与上下文窗口 | **AI 为啥聊着聊着就失忆？这事得怪 Token！** | 痛点提问 + 具体物 + 不剧透 |
| 第 08 讲：Agent 智能体入门 | **会自己跑腿的 AI 来了！Agent 凭啥这么能干？** | 反差承诺 + 悬念提问 + 具体物 |
| 第 10 讲：RAG 检索增强生成全解析 | **AI 满嘴跑火车？给它配个图书管理员！这毛病能治！** | 痛点提问 + 形象比喻 + 承诺 |

> 注意：钩子标题只「提问、给画面、给承诺」，**绝不写出寓言的谜底 / 反转 / 结论**。
> 比如第 06 讲点到「怪 Token」即止，至于上下文窗口怎么把记忆挤掉，留给正文。

## 三、各平台字数与策略

| 平台 | `platform` 值 | 硬上限 | 建议 | 策略 |
| --- | --- | --- | --- | --- |
| 公众号 | `wechat` | ≤ 64 字 | **≤ 30 字** | 列表页 / 推送会截断，**钩子必须落在前 30 字**，别把问号感叹号留到后半段 |
| 小红书 | `xiaohongshu` | ≤ 20 字 | ≤ 18 字 | 标题太短放不下长钩子：**超长就只留「：」后的副标题**；完整长钩子放**正文首行 / 封面图大字** |
| 知乎 | `zhihu` | ≤ 100 字 | 前 20 字抓人 | 可以长，但**前 20 字要有痛点 / 悬念**；知乎正文优先，标题别堆形容词 |
| CSDN | `csdn` | ≤ 100 字 | 前 20 字抓人 | 技术读者也吃具体问题，标题别写成课程目录 |
| 掘金 | `juejin` | ≤ 100 字 | 前 20 字抓人 | 与分类/标签一致，别为了钩子偏离技术主题 |

**同一个钩子按平台拆多份**（以第 10 讲为例）：

- 公众号（前 30 字自带完整钩子）：`AI 满嘴跑火车？给它配个图书管理员！`
- 小红书：标题用短钩子 `AI 为啥满嘴跑火车？`，封面 / 正文首行再放长版 `给它配个图书管理员，这毛病能治！`
- 知乎（前 20 字抓人）：`AI 满嘴跑火车？给它配个图书管理员！一个寓言讲透「检索增强」`
- CSDN / 掘金：`AI 满嘴跑火车？给它配个图书管理员！一个寓言讲透 RAG`

## 四、红线（不可越）

1. **标题必须与文章内容相关**：寓言里讲了什么概念，标题就指向什么；别为了点击挂无关噱头。
2. **不做欺骗式标题党**：不承诺文章给不了的东西（没有「保过」「必涨粉」就别写）。
3. **不剧透答案 / 结局**：寓言的谜底、反转、最终结论**不进标题**——标题负责勾人，正文负责兑现。
4. **提问要在正文有回答**：标题抛出的每个「？」，正文都要正面回答，否则就是骗点击。

## 五、配套校验脚本

创意靠人（按上面公式写），长度与规整靠脚本。同目录 `title.mjs` 只做机械校验：去空白 /
去不可见字符 / 按平台截断 / 统计问号感叹号，**不改写创意**。

```bash
# 在 skills 根目录执行；platform ∈ wechat | xiaohongshu | zhihu | csdn | juejin
node _publish_core/title.mjs --title "AI 满嘴跑火车？给它配个图书管理员！" --platform wechat
```

返回 `{ ok, title, warnings }`：

- `ok=true`：长度合规，`title` 可直接拿去发。
- `ok=false`：被截断 / 平台未知 / 标题为空——**回到第一步重写更短的钩子**，别直接发被截断的残句。
- `warnings`：含截断说明、小红书取副标题说明、以及「建议加问号/感叹号增加节奏感」这类节奏提醒
  （节奏提醒是建议，不阻断发布）。
